FIXES IMPLEMENTED (v1.31 work) -- pending in-game verification (see CLAUDE.md checklists):

1. [Nexus EN] "if you holster your weapon and pull it back out, rather than scaling off of the
   seal (+200 for me) it applies the static 75 damage seen on grease"
   -> ROOT CAUSE: re-applying the bare SpEffect id can't know the catalyst scaling that was
      computed at cast time and stored in the live effect INSTANCE, so the fresh instance gets
      the param's base (grease-level) values.
   -> FIX: the mod now snapshots each persistable live effect's entry state every tick
      (engine countdown at entry+0x40, cast-time payload at +0x50..0x78) and copies it back
      onto the entry right after any of OUR re-applies (weapon-memory restore, death/fast
      travel re-apply). [persistence] restore_buff_power = 1. Payload writes are gated to
      float-looking dwords on both sides, so a layout drift on a future game patch can
      corrupt nothing. Each restored dword is logged ("entry restore: ... payload restored
      [ +0x54 1->2.67 ]") -- those log lines will pin the exact magnitude field for us.

2. [Nexus CN] "in 1.30, buffs from incantations such as Golden Vow disappear after death
   (1.21 kept them, but leaked buffs into other characters on profile switch)"
   -> ROOT CAUSE (three stacked issues):
      a) 1.30's source allowlist only tracked Magic refIds that resolve DIRECTLY as SpEffects.
         AOE/ally incantations (Golden Vow = Magic 6600) apply their buff through a BULLET,
         and many buffs sit behind replace/cycle chains -- their ACTIVE ids (1660000/1660002
         family) were never tracked, so they were dropped from `remembered`.
      b) The death freeze needed >= 2 buffs stripped in one tick; a death with a single
         tracked buff slipped past it (more likely in 1.30, since the allowlist no longer
         counts talisman noise).
      c) The 1.21-era character-switch leak was only fixed when session/weapon-memory was on.
   -> FIXES:
      a) Discovery now resolves Magic refs per refCategory (SpEffect AND Bullet, with chain
         walking + spawn-on-hit child bullets) -- Golden Vow & friends are tracked.
      b) Death is now detected AUTHORITATIVELY via player hp == 0 (ChrIns modules -> data
         module +0x138). Any death freezes `remembered`, single buff included; the >=2-drop
         heuristic stays as fallback if the hp read fails. This also finally implements the
         independent keep_after_death / keep_after_fast_travel toggles.
      c) Character-switch detection is now ALWAYS on (GameDataMan is resolved regardless of
         features); switching profiles clears the previous character's buffs even with
         session persistence off.

3. Ashes of war fully expanded: instead of the hard-coded 32-id list, discovery now scans
   BehaviorParam_PC/BehaviorParam (refType SpEffect/Bullet, beneficial-gated) -- every AoW
   self-buff, vanilla + DLC + overhaul-added, is tracked. Weapon-bound vs character-wide is
   decided param-driven: effects sharing a grease spCategory (weapon enchants) stay
   weapon-bound; everything else survives any swap. The old 32-id list remains as a seed.

4. Overhaul compatibility: consumable scan now covers ALL EquipParamGoods rows (any
   sortGroupId) with the self+beneficial field gate, so overhaul items are discovered
   wherever they sort. Debuff policy: pure debuffs never pass the gate; status-ailment procs
   stay hard-blocked by id; items with a downside rider persist via their beneficial effect
   node. New [persistence] never_persist_ids escape hatch to drop anything unwanted.
   NOTE: physick tears now persist (they pass the field gate) -- users who dislike that can
   add their ids to never_persist_ids.

5. Steam Deck / Proton: the DLL was built with /MD (dynamic CRT) and needed the MSVC
   redistributable inside the game's proton prefix -- absent on Deck, so LoadLibrary failed
   silently and the mod "did nothing". Now built with /MT (CMAKE_MSVC_RUNTIME_LIBRARY
   MultiThreaded): the release DLL imports ONLY kernel32.dll (verified) and loads on a bare
   prefix. SAME FIX APPLIES TO THE SIBLING MODS (they all default to /MD).
